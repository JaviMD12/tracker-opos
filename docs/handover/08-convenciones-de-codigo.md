# 8. Convenciones de código a seguir

- **`app/models/` es un paquete**, no un `models.py` plano — un archivo por modelo (`marca.py`, `sesion_estudio.py`, `resultado_simulacro.py`...). Esto se ha confundido repetidamente entre sesiones (se ha pedido "actualizar `models.py`" varias veces cuando ese archivo no existe) — si ves esa instrucción, es casi seguro que se refiere a `app/models/`.
- **Nombres en español, sin acentos, en identificadores/tablas/variables** (`usuario_id`, `fecha`, `duracion_minutos`, `titulo_plaza`...). El contenido de texto visible al usuario (strings, prompts) sí lleva tildes en UTF-8 correctamente — si se ven rotas en una consola de Windows, es el codepage de la terminal, no un bug real.
- **Reusar el campo/patrón que ya existe antes de crear uno nuevo con otro nombre.** Ejemplos reales de esta ronda: se pidió crear `is_premium` y se reusó `Usuario.is_pro` (ya existía con el mismo propósito); se pidió `StudyLog` con `user_id` y se creó `SesionEstudio` con `usuario_id` para mantener consistencia.
- **Todo router de datos nuevo**: `Depends(get_current_user)` + `.filter(Modelo.usuario_id == current_user.id)`. Si además es una funcionalidad de pago, añadir `if not current_user.is_pro: raise HTTPException(403, ...)` — ver el patrón ya replicado en `convocatorias.py`, `tutor.py`, `simulacros.py`.
- **Errores de SDKs externos** (Stripe, Gemini, Authlib, httpx): capturar la excepción base del SDK, envolver en `HTTPException(502, ...)`. Para las excepciones de `stripe`, preferir el import directo (`from stripe import SignatureVerificationError` / `stripe.SignatureVerificationError`) en vez de `stripe.error.X` — esa segunda forma dio un error real y confuso con la versión actual del SDK (ver [02-autenticacion-y-pagos.md](02-autenticacion-y-pagos.md)). Para Gemini, la excepción base es **`google.genai.errors.APIError`** (ya no `openai.OpenAIError` — el proyecto migró de OpenAI a Gemini por completo, ver [04-tutor-ia-y-rag.md](04-tutor-ia-y-rag.md)).
- **Inicialización perezosa** para todo lo que dependa de una API key externa o de un recurso costoso (Stripe, Gemini, el vectorstore de Chroma) — nunca llamadas de red/disco al importar un módulo.
- **Validar la forma real de lo que devuelve un LLM antes de usarlo**, no solo que el JSON parsee. `response_mime_type="application/json"` (o el equivalente de OpenAI) garantiza JSON *sintácticamente* válido, no que tenga la forma de objeto esperada — un `isinstance(datos, dict)` antes de `datos.get(...)` evita un `TypeError`/`AttributeError` en producción si el modelo alguna vez devuelve `null`, una lista o un string. Ver el audit de `scraper_boletines.py` en [05-tablon-convocatorias-scraper.md](05-tablon-convocatorias-scraper.md) para el caso real que motivó esto.
- **Los scripts offline que tocan la BD o llaman a Gemini/Stripe cargan su propio `load_dotenv()`** al principio, antes de importar nada de `app.*` — `app/database.py` lee `DATABASE_URL` de `os.environ` directamente al importarse (no llama a `load_dotenv()` él mismo), así que un script que importe `app.database` sin haber cargado antes el `.env` cae silenciosamente a SQLite local aunque se esté ejecutando en el VPS con Postgres real. Ya ha pasado por error en esta sesión al depurar datos en producción — comprobar siempre `engine.dialect.name` si hay duda de contra qué base de datos se está hablando.
- **Reconstruir `chroma_db_data/` en local y en el VPS a la vez agota la cuota de embeddings de Gemini** (es un límite por minuto, no diario) — hacerlo siempre en serie, esperando a que termine uno antes de lanzar el otro.
- **Despliegue a producción**: `git push` en local → `git pull` por SSH en el VPS → **`systemctl restart tracker-opos.service` solo si cambió código Python** (no hay `--reload` en producción). Los cambios de frontend (`.html`/`.css`/`.js`) son estáticos, se sirven en caliente sin reiniciar nada.
- **Al terminar una sesión con cambios grandes de arquitectura/infraestructura**, sincronizar `docs/handover/` explícitamente (pedirlo o hacerlo de oficio) — estos documentos se han quedado desactualizados más de una vez porque nadie los tocó tras cambios importantes (ver el punto 15 de [07-deuda-tecnica-y-pendientes.md](07-deuda-tecnica-y-pendientes.md)).
- **Nunca `innerHTML` con contenido generado por el LLM sin `DOMPurify.sanitize(marked.parse(...))` primero** — patrón usado en el chat del Tutor IA, el plan de estudio del Tablón y en cualquier render de Markdown nuevo.
- **Frontend es Vanilla JS puro** (`frontend/js/main.js`, un único archivo, sin build step, sin módulos ES, sin framework) — mantener ese estilo al añadir features nuevas.
- **Antes de dar por bloqueada/protegida una funcionalidad de pago, verificar el 403 real del backend**, no solo el estado visual del frontend (`localStorage`). El botón "Simular pago" (dev) nunca activa `is_pro` de verdad — ver [02-autenticacion-y-pagos.md](02-autenticacion-y-pagos.md).
- **Antes de reconstruir una UI ("vamos a añadir un mapa de calor/heatmap...")**, comprobar si ya existe algo parecido de una sesión anterior con datos mock — ha pasado más de una vez en esta ronda (el heatmap de actividad ya existía visualmente antes de conectarlo a datos reales). Reusar y conectar, no duplicar el contenedor.
- **El CDN "Play" de Tailwind (`cdn.tailwindcss.com`) no garantiza que una variante responsive gane el cascade sobre una utilidad base en el mismo elemento** — a diferencia del build normal de Tailwind, donde `class="hidden lg:flex"` es un patrón oficial y fiable. Bug real (2026-08-10): el menú móvil del sidebar usaba justo ese patrón y el sidebar entero quedaba invisible en escritorio. Fix: CSS propio explícito con `@media (min-width: ...)` para cualquier toggle de visibilidad crítico (mismo patrón que ya usaba `.auth-image-panel`), no depender de la combinación `hidden lg:flex`/`md:flex`/etc. de Tailwind CDN para eso.
- **Cualquier `<input>`/`<textarea>` con `font-size` por debajo de 16px dispara el zoom automático de iOS Safari** al enfocarlo, y ese zoom se queda "pegado" tras cerrar el teclado, descuadrando toda la pantalla. Bug real encontrado y corregido (2026-08-10): `.field` estaba a `0.925rem` (~14.8px), afectaba a los 21 campos de la web. Mantener siempre `font-size: 16px` (o más) en cualquier campo de formulario.
- **Patrón SMTP establecido y reutilizado 3 veces** (`routers/contacto.py`, `routers/auth.py::_enviar_email_recuperacion`, `routers/waitlist.py`): variables `SMTP_SERVER/SMTP_PORT/SMTP_USER/SMTP_PASSWORD` del `.env` (Gmail con contraseña de aplicación en producción), función privada que se ejecuta en un `BackgroundTask` (nunca bloquea la respuesta HTTP esperando a SMTP), y cualquier fallo se captura y solo se registra con `print()` en el log del servidor — nunca se revela al usuario ni rompe la petición. Reusar este mismo patrón para cualquier email nuevo, no inventar uno distinto.
- **Patrón de feature flag "pausable" (`ENABLE_STRIPE` en `routers/pagos.py`)**: variable de entorno leída una vez a nivel de módulo, con un default que **preserva el comportamiento actual** si la variable no existe (`os.environ.get("ENABLE_STRIPE", "true").lower() != "false"`) — desplegar el código que introduce el flag nunca cambia nada por sí solo, hace falta añadir la variable explícitamente para activarlo. Replicar este mismo patrón para cualquier interruptor temporal futuro, en vez de uno que invierta la lógica (flag ausente = comportamiento nuevo).
- **Cuentas de prueba (`test-*@local.dev` u otro patrón obvio) creadas durante una sesión, tanto en local como en producción, se limpian siempre al terminar** — verificar contra la base de datos real (`SELECT ... WHERE email LIKE '%test%' OR ...`), no fiarse de memoria de lo que se fue borrando sobre la marcha. Ha quedado deuda de sesiones anteriores más de una vez (18 cuentas sueltas encontradas en local en una sola pasada el 2026-08-10).
- **Si Gemini devuelve `401 UNAUTHENTICATED` con `"Expected OAuth 2 access token..."` / `reason: ACCESS_TOKEN_TYPE_UNSUPPORTED`, sospechar primero de una restricción de IP/aplicación en la clave en Google Cloud Console**, no de un bug de código o del SDK — es un mensaje distinto al `429 RESOURCE_EXHAUSTED` de cuota (ese sí es un problema de cuota, ver [04-tutor-ia-y-rag.md](04-tutor-ia-y-rag.md)). Caso real (2026-08-11): la misma clave funcionaba en AI Studio y desde el ordenador del usuario, pero fallaba igual con el SDK, con `requests` puro y con `curl` nativo **solo desde el VPS**, descartando red/DNS/hora del sistema. Un `curl -H "x-goog-api-key: $GOOGLE_API_KEY" https://generativelanguage.googleapis.com/v1beta/models` aísla rápido si es la clave o el código, sin necesidad de tocar el pipeline de RAG para diagnosticarlo.
- **Al indexar un PDF paginado nuevo en `app/conocimiento/`, comprobar si repite cabecera/pie de página y si alguna etiqueta de sección (ej. un identificador tipo "BC-2") aparece solo una vez al principio de un bloque multi-página.** Ambos patrones degradan la recuperación semántica en silencio (sin error, sin excepción) — el primero porque la cabecera repetida compite con el contenido real en la búsqueda; el segundo porque el contenido que sigue en páginas posteriores pierde la referencia a qué sección pertenece al trocearse. `_quitar_cabeceras_repetidas()` y `_marcar_paginas_con_parque_actual()`/`_propagar_marcador_a_fragmentos()` en `ai_tutor.py` ya cubren estos dos casos de forma genérica (no solo para el documento que los motivó, TEMA-36) — si aparece un tercer patrón parecido, seguir el mismo enfoque: detectar, marcar en metadata a nivel de página, y propagar a nivel de fragmento (después de trocear, no antes).
- **El loader de `app/conocimiento/` (`_cargar_documentos_conocimiento()`) solo indexa `.pdf` y `.txt`** — un `.docx`/`.xlsx` depositado ahí se ignora en silencio, sin ningún error ni aviso. Si se necesita indexar esos formatos, convertir a PDF/TXT primero (no hay `python-docx`/`openpyxl` en `requirements.txt`).
